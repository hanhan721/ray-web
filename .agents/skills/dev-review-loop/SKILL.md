# 按批次开发与独立审查

复用当前主 Agent 开发，每个需要审查的功能批次交给一个独立子 Agent；按风险验证，控制重复工作。

## 启用与范围

- 仅在用户明确调用本技能或其命令入口时启用；创建、编辑或讨论本技能不算启动开发循环。
- 任务目标、阶段范围和停止条件来自用户本次指令及已有授权；调用本技能不自动授权完成全部阶段、修改后端或发布。
- 下述路径相对项目根。读取适用的 `AGENTS.md`；涉及实施计划时按需读取 `docs/implementation-plan.md` 当前阶段、决策和验收条件。沿用已有计划，不为普通任务重新做整套规划。
- 开始先查看 `git status` 与相关差异，区分已有修改和本批改动；保护其他会话成果，不与其同时写同一批文件。没有明确目标且上下文也无法确定时，只询问缺失目标。

## 能力与分工

- 当前主 Agent 负责实现、运行必要检查、核实问题、修复和更新进度；沿用客户端已有模型设置。
- 实际调用宿主提供的通用子 Agent 做独立 Reviewer。Cursor 使用当前暴露的子 Agent 工具；OpenCode V2 使用 `subagent`，V1 按其实际 `task` 工具。以当前工具清单与版本为准，不猜参数、不为此安装插件或创建 Agent 配置。
- Reviewer 使用独立上下文，只读源码、契约和验证证据，不修改代码或运行会改变状态的命令；补充验证由主 Agent 按项目策略执行。只读提示词不是强制权限隔离。
- 没有可用子 Agent 时说明能力缺失，可以推进其他已授权工作，但不得把主 Agent 自查称为独立 Review；需要独立审查的部分保留为未完成。

## 按风险安排批次

- 改动前声明项目规定的 L0-T / L0-C / L0-V / L1 / L2 与确切验证命令，遵循 `AGENTS.md` 和上级测试策略。
- 用户未特别要求时，L0 按既有策略检查即可，不单独启动 Reviewer；L1 按完整功能或修复批次审查，L2 同时检查受影响契约与调用方。不要按每个文件、函数或样式值拆分审查。
- 视觉和页面布局按需使用 `frontend-design`；Vue、Router、Pinia、shadcn 工作使用对应已有技能；库 API、组件查询和浏览器验收按需使用当前可用 MCP。只加载本批需要的内容。

## 开发、审查、修复

1. 实现本批目标，按等级执行必要检查；检查失败先修复。以命令输出和真实操作为证据，区分模拟验证与真实联调，不为获得绿灯修改规格。
2. 检查通过后暂停写入本批文件，再实际调用一个 Reviewer；一次审查同时核对需求符合性和代码质量。
3. 交给 Reviewer：本批目标与验收条件、适用规则路径、本批变更清单、相关差异或基线、验证命令及实际结果。包含相关未跟踪新文件，不能只给 `git diff`；无需复制整段会话或反复提交无关全仓内容。
4. 核实发现，修复有依据的问题；不同意时给出代码或行为证据，不通过降低验收条件消除问题。修复后只重验受影响内容，再交 Reviewer 检查修复和可能回归。
5. 验收通过后更新已有进度记录并继续授权范围内下一批，简短汇报，不默认停下来询问是否继续。

### Reviewer 交接指令

结合上述材料，向通用子 Agent 明确交代：

> 请独立审查本批变更。读取适用规则与实际源码，覆盖未跟踪的新文件和必要调用方；不以实现者的完成声明代替证据。只读，不修改源码或执行状态变更操作。
> 检查需求与真实契约、功能行为、回归风险、必要的权限和数据边界，以及本批 UI 的标签、键盘和焦点行为。验证规模遵循项目分级策略。
> 只报告有依据的问题，写明严重程度、文件行号、触发条件、实际影响和证据；不要求一定找出问题。可选风格、命名或抽象偏好不阻塞交付。
> 返回 PASS（本批验收满足）、NEEDS_FIX（有待修的明确问题）或 UNVERIFIED（缺少必要证据），并列出发现和未覆盖范围。需要补验时给出最小验证建议，不擅自升级全量测试。

## 开销、停止与交付

- 默认每批最多 3 次 Review（首次加最多 2 次复审），用户可明确调整。达到上限仍不满足验收时记录未解决问题与证据，继续不受影响的独立任务；没有独立工作可做时集中报告，不将未通过的部分标为完成。
- 只因新改动、失败或尚未解决的疑点追加验证，不重复已通过且未受影响的检查；不强制 TDD，不自行运行全量测试。
- 复用主开发上下文，给 Reviewer 精简且完整的任务材料；只有需要隔离新目标或旧上下文过多时才新建审查上下文，不并行修改同一批文件。
- 明确的功能错误、契约偏离、权限或数据风险、必要可访问性缺陷和项目硬约束必须处理；可选改进单独记录。
- 真正缺失的业务规则、后端契约或其他确认边界按现有计划和用户授权处理，先完成独立工作，不为日常工程选择新增审批。
- 不自动提交、推送、部署、切换分支或创建 worktree；仅在有对应授权时执行，不为闭环放宽客户端权限。
- 交付简述完成范围、实际独立审查次数、验证结果、工具不可用或未覆盖事项，以及剩余问题。只有验收满足、适用的独立审查已通过且没有待修明确问题时才标记完成。
